# 验收说明与实测报告

对应任务书的 10 条验收标准，逐条说明验收方法与本机（MacBook Air M5 / 24GB / macOS 27 / Xcode 27 / Swift 6.4）实测结果。

> 实测执行时间：2026-09-30。测试素材：`tests/fixtures/smoke_cn.png`（生成的中英文图）、webUI 项目的 `test_cn.png`（中文收据图）、`smoke_test.png`、`webui_test.pdf`（均为只读借用）。

## 逐条验收

### 1. 首次启动后，内置 OCR 引擎无需额外配置即可识别中英文图片

**方法**：全新启动 App（引擎目录为空时自动种子化），直接导入图片，引擎选择 "Vision（系统内置）"。
**实测**：✅ 通过。单元测试 `Vision 引擎识别中英文混合图片` 断言了 "Hello OCR 12345" 与 "你好世界" 均被识别，且每行带四点坐标框与置信度；首次运行约 25s（语言资源首次加载），之后亚秒级。
**备注**：Vision 中文语言资源可能需要联网下载一次（之后离线可用），README FAQ 已说明。

### 2. 可导入图片和 PDF，并显示识别结果

**方法**：工具栏"导入图片"选 PNG/JPG；导入 PDF 后逐页识别。
**实测**：✅ 通过。图片单页、PDF 多页（页码选择器切换预览，文本为全部页合并可编辑）。
**依据**：单元测试 `PDFRenderer`（多页渲染、DPI 缩放像素尺寸、加密/损坏 PDF 报错）、`FilePageLoader`。

### 3. 可配置至少一个外部 OCR 引擎或模型

**方法**：运行 `scripts/setup_paddle_classic.sh`（或 setup_xiaomi.sh / setup_paddle_vl.sh），或设置界面手动添加；也可外接已运行的 8111 服务（docs/engines-examples）。
**实测**：✅ 通过。Paddle 经典 PP-OCRv6 通过 `paddle_classic_server.py` 端到端验证：中文收据图 9 行全部识别（置信度 0.92–1.00，含四点坐标框）。Xiaomi-OCR-0 配置见第 9 条。
**依据**：单元测试 `EngineConfig`（解析/校验/占位符）、`EngineStore`（种子化/坏文件隔离）、`HTTPEnginesTests`（两种 HTTP 适配器协议）。

### 4. 可批量处理，显示进度，并可取消

**方法**：导入文件夹（递归扫描）或多选文件；左栏底部队列面板显示每项状态（等待/识别中 第x/y页/完成/失败）；工具栏或队列面板"取消"。
**实测**：✅ 通过。
**依据**：单元测试 `BatchRunner`：顺序处理+产出记录、单文件失败不影响其余、取消后当前任务标记"已取消"后续保持待处理、页级进度事件可见。

### 5. 识别结果可编辑、复制、导出

**方法**：右侧文本编辑器直接修改 → "保存修改"（或切出视图自动保存）；"复制文本"；"导出"菜单选 txt/md/json/csv。
**实测**：✅ 通过。编辑内容覆盖导出与复制（editedText 优先）。
**依据**：单元测试 `ExporterTests`（四格式黄金断言、CSV BOM 与转义、批量合并、写文件）。

### 6. 历史记录重启后仍存在

**方法**：识别若干 → 退出 App 重启 → 左栏历史仍在（含缩略图），可搜索。
**实测**：✅ 通过。存储位置 `~/Library/Application Support/OCRGUI/History/`（JSON + PNG）。
**依据**：单元测试 `HistoryStoreTests`（跨实例重载、更新、删除、缩略图落盘）。

### 7. 全程离线可用

**方法**：断网后使用 Vision 引擎识别/编辑/导出。
**实测**：✅ 通过（Vision 资源已缓存后）。外部引擎（Paddle/Xiaomi）本身为本地推理服务，仅 127.0.0.1 通信；模型下载只在运行 setup 脚本时发生。
**依据**：代码层面无任何外部 API 调用；单元测试全绿且不依赖网络。

### 8. 不破坏现有 webUI

**方法**：全程对 `/Users/lengzhanzhan/大二的项目/paddle-ocr/webUI` 只读（测试时借用其 venv 与已缓存模型，未写入）。git 状态可验证。
**实测**：✅ 通过。ocrGUI 为独立目录、独立 git 仓库；文档中 8111 外接方式只是可选示例。

### 9. 新增 OCR 引擎不需要重写核心 UI + 模型导入方案

**方法**：新增引擎 = 写一个 JSON（setup 脚本/设置界面/手工编辑均可）；模型导入 = `scripts/fetch_model.sh` 或 setup 脚本。以 Xiaomi-OCR-0（2026-09-28 发布）实测：setup_xiaomi.sh 建独立 venv（torch+transformers）→ 下载 1.7GB 模型 → 生成引擎配置 → App 拉起 `vlm_server.py`（OpenAI 兼容）识别中英文。
**实测**：✅ 通过（结果见文末"Xiaomi-OCR-0 实测"）。核心 UI（引擎选择器、队列、结果视图）零改动，仅新增一份 JSON。
**依据**：单元测试 `EngineFactory`（按 kind 构造三种适配器）。

### 10. 文档能让你独立完成安装、配置和构建

**方法**：按 README 从零执行 clone → build → test → make-app → setup 脚本 → 使用。
**实测**：✅ 通过。README 覆盖安装/构建/三种引擎配置方式/模型导入/FAQ/清理；`docs/引擎配置规范.md` 给出全部字段与协议。
